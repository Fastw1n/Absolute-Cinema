# Absolute Cinema / FilmGraph

Учебное iOS-приложение на SwiftUI и MVVM: поиск фильмов через TMDB, карточка фильма и список личных оценок с комментариями. Минимальная версия — iOS 17.

## Запуск

1. Откройте `AbsoluteCinema.xcodeproj`, выберите схему `AbsoluteCinema` и iPhone Simulator либо устройство.
2. Скопируйте `AbsoluteCinema/Configuration/TMDBConfig.example.plist` в `TMDBConfig.plist` в той же папке.
3. В поле `readAccessToken` впишите **TMDB API Read Access Token** из настроек вашего аккаунта TMDB.
4. Запустите приложение. На главной введите название: результаты появятся под строкой после паузы 350 мс.

На текущем компьютере локальный файл уже настроен предоставленным токеном. `TMDBConfig.plist` исключён из Git; его нужно создать заново на другом компьютере. После изменения токена пересоберите приложение. Токен не выводится приложением в журнал. Локальная конфигурация — способ настройки учебной сборки, она не является защищённым хранилищем секретов в установленном приложении.

Моков в пользовательском приложении нет. Данные и постеры приходят из TMDB; тестовые JSON и подставные ответы находятся только в тестовых таргетах.

## Пользовательский сценарий

- На вкладке «Поиск» найдите фильм и откройте карточку.
- Выберите личную оценку 1–10. По желанию впишите свободный многострочный комментарий.
- Нажмите «Сохранить оценку»: оценка, комментарий и сведения фильма сохраняются вместе.
- Откройте «Мои оценки». Переключайте сортировку по дате оценки или личному рейтингу.
- Откройте фильм из списка, измените оценку/комментарий и сохраните.
- «Убрать оценку и комментарий» в карточке или свайп строки списка удаляет личную запись.

Изменение оценки обновляет её дату. Редактирование только комментария либо повторное сохранение той же оценки не меняет дату. При одинаковом рейтинге используется дата, затем ID — порядок стабилен. Рейтинг TMDB и личная оценка подписаны отдельно; личные данные не отправляются в TMDB.

## Почему два хранилища

| Инструмент | Что хранится | Причина |
|---|---|---|
| SwiftData | Фильмы с личной оценкой, комментарием и датой; снимок сведений фильма | Коллекция должна переживать перезапуск, читаться без сети, изменяться, удаляться и сортироваться без дублей |
| UserDefaults | Выбранная сортировка списка | Это небольшая настройка интерфейса, которую удобно восстанавливать при запуске |

Без интернета доступны список оценённых фильмов и их сохранённые текстовые карточки, личные оценки и комментарии. Неудачное обновление из API показывает сообщение и оставляет сохранённые сведения. Постеры отдельно на диск не сохраняются: при недоступности изображения используется заглушка. Поиск и впервые открываемые фильмы требуют сети.

## CRUD для показа преподавателю

| Операция | SwiftData | UserDefaults |
|---|---|---|
| Create | Впервые сохранить оценку с комментарием | Выбрать сортировку — записать ключ |
| Read | Открыть «Мои оценки» или карточку сохранённого фильма | Перезапустить приложение — прочитать сортировку |
| Update | Изменить оценку/комментарий без создания дубликата | Выбрать другую сортировку |
| Delete | Удалить оценку вместе с комментарием | «Сбросить» удаляет ключ сортировки и возвращает порядок по умолчанию |

Сброс сортировки не удаляет фильмы. Все операции SwiftData явно вызывают `ModelContext.save()`. Ошибка сохранения откатывает изменения базы и отображается в интерфейсе; текст формы остаётся доступен для повторного сохранения.

## MVVM и структура

- `Models/`: `Movie`, `MovieSummary`, `SavedRating`, `RatingSortOrder`.
- `Features/Search/`: ввод запроса, задержка, отмена старых задач и защита от устаревших ответов.
- `Features/MovieDetails/`: состояние загрузки карточки и форма личной оценки/комментария.
- `Features/Ratings/`: список, сортировка и удаление оценок.
- `Data/Network/`: отдельный actor API-клиента, URLSession, Codable и преобразование DTO.
- `Data/Repositories/`: протоколы и реализации источников данных; `RatingRepository` содержит CRUD и правила оценки.
- `Data/Persistence/`: SwiftData-модель `RatedMovie` и настройки UserDefaults.
- `AbsoluteCinemaApp.swift`: создание общих зависимостей и навигация двух вкладок.

View отображает состояние и передаёт действия во ViewModel. ViewModel на MainActor вызывает репозиторий. Сетевой клиент изолирован собственным actor; значения данных — Sendable. Один ModelContainer и репозиторий оценок обслуживают все экраны. Observation обновляет список при изменении записей. Поиск отменяет старую задачу и дополнительно проверяет актуальность ответа.

## Проверки

Product → Test запускает юнит-тесты и обычный UI-тест без зависимости от живого API. Проверяются декодирование, HTTP-ошибки, поиск и его отмена, CRUD, комментарии, дата оценки, сортировка, сброс UserDefaults и повторное открытие настоящего дискового хранилища.

`LiveFlowTests` — дополнительный UI-прогон реального API, по умолчанию пропускается. Для него нужен настроенный токен и сеть. Он сохраняет собственную тестовую оценку в тестовом симуляторе, проверяет изменение, восстановление после перезапуска и удаление.

```sh
TEST_RUNNER_FILMGRAPH_LIVE_SMOKE=1 xcodebuild test \
  -scheme AbsoluteCinema \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -only-testing:AbsoluteCinemaUITests/LiveFlowTests
```

Для ручной защиты: поиск → карточка → оценка и комментарий → список → изменение → обе сортировки → перезапуск без сети → сохранённая карточка → удаление → сброс сортировки → повторный перезапуск.

## Границы текущего этапа

Реализованы три основных экрана: поиск с выдачей на той же странице, карточка и «Мои оценки». Четвёртый экран из исходных требований, статусы «Хочу посмотреть / Просмотрено», каталог и рекомендации остаются следующим этапом. Условия этого этапа: два инструмента хранения, обоснование сохраняемых данных и CRUD.

Данные и изображения: TMDB. This product uses the TMDB API but is not endorsed or certified by TMDB.
