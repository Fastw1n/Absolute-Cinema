# План ближайшей реализации: поиск, карточка, мои оценки

1 октября 2026. Статус: ближайший этап реализован и проверен. Свободный комментарий сохраняется вместе с оценкой.

Этот план уточняет ближайший этап DEVELOPMENT_PLAN.md. Приоритет — текущие решения пользователя: реальные данные, поиск на главной и список оценённых фильмов. Исходный документ остаётся ориентиром для дальнейшей разработки.

## Подтверждённый сценарий

- Главная изначально содержит поисковую строку и краткую подсказку, без подборок фильмов.
- Результаты появляются под строкой по мере поиска и занимают основную область той же страницы.
- Нажатие открывает карточку выбранного фильма.
- Фильм автоматически попадает в раздел «Мои оценки» после выставления личной оценки 1–10. Отдельная кнопка лайка не нужна.
- В разделе доступна сортировка по дате оценки либо по личной оценке.
- Сохраняются MVVM, SwiftUI, SwiftData и согласованная тёмная тема без излишнего декора.

На этом этапе три содержательных экрана: главная с результатами, карточка, мои оценки. Требование минимум четырёх экранов из исходного документа пока не закрывается; отдельный четвёртый экран определим на следующем этапе.

## Обязательные требования сегодняшнего занятия

Прямые цитаты преподавателя, переданные пользователем:

- «определиться со способом хранения данных (пример userdefaults + swiftdata)»;
- «обосновать причины сохранения данных»;
- «операции crud должны быть реализованы»;
- «2 инструмента минимум! (userdata + swiftdata подходят)».

Для реализации выбираем **UserDefaults + SwiftData**. Под userdata в плане понимается UserDefaults. Оба инструмента обязательны, используются в реальных пользовательских действиях и проверяются после перезапуска.

| Инструмент | Данные | Почему сохраняем |
|---|---|---|
| SwiftData | Оценённые фильмы: movieID, сведения для списка, личная оценка и дата её изменения | Это пользовательская коллекция, которую нельзя терять после закрытия приложения. Она должна читаться без сети, обновляться, удаляться и сортироваться без дублей |
| UserDefaults | Выбранная сортировка «Моих оценок» | Это небольшая настройка интерфейса. После перезапуска пользователь получает предпочитаемый порядок, а не выбирает его снова |

CRUD должен быть виден в интерфейсе:

| Операция | SwiftData | UserDefaults |
|---|---|---|
| Create | Первая оценка создаёт запись фильма | Первый выбор сортировки записывает настройку |
| Read | Открытие «Моих оценок» читает сохранённые записи; карточка восстанавливает личную оценку | При запуске читается выбранная сортировка; при отсутствии ключа применяется значение по умолчанию |
| Update | Изменение оценки обновляет существующую запись и дату | Выбор другой сортировки обновляет настройку |
| Delete | «Убрать оценку» удаляет запись фильма | «Сбросить сортировку» удаляет ключ и возвращает порядок по умолчанию |

Сброс сортировки выполняется удалением ключа UserDefaults, а не записью значения по умолчанию: на защите можно показать именно удаление сохранённой настройки. Сброс не затрагивает оценки фильмов.

Необходимо отличать состояние в памяти от сохранения на диске. Проверка: полностью завершить процесс приложения и запустить снова без сети; список, оценки, даты и выбранная сортировка должны восстановиться. После удаления записи и сброса настройки повторить запуск и подтвердить, что удалённые данные не появились снова.

## Правила, предлагаемые к утверждению вместе с планом

- Поиск запускается после паузы 350 мс в наборе. Кнопка поиска на клавиатуре может запустить его сразу, не дублируя запрос.
- Пустой запрос и строка из пробелов не вызывают сеть. Очистка строки отменяет текущий поиск и возвращает начальное состояние.
- Каждый новый запрос отменяет предыдущую задачу. Перед изменением состояния проверяется актуальность запроса, включая ошибки: старый ответ не перезапишет новую выдачу.
- Личная оценка — целое число 1–10. Она не отправляется в TMDB и не меняет рейтинг сервиса.
- «Убрать оценку» удаляет личную запись и исключает фильм из «Моих оценок».
- Комментарий — свободный и необязательный, сохраняется вместе с оценкой. Изменение только комментария не меняет дату оценки. Удаление оценки удаляет комментарий.
- Изменение оценки обновляет дату оценки. Повторный выбор того же числа не меняет дату. Повторная оценка после удаления получает новую дату.
- Сортировка «Сначала недавно оценённые»: дата по убыванию, затем movieID для стабильного порядка.
- Сортировка «Сначала высокая оценка»: личная оценка по убыванию, затем дата по убыванию и movieID.
- Выбранная сортировка сохраняется между запусками в UserDefaults. Значение по умолчанию — сначала недавно оценённые.
- Существующий сценарий «Хочу посмотреть / Просмотрено» предлагается отложить: на этом этапе карточка управляет личной оценкой, а раздел показывает все оценённые фильмы. Возвращение статусов — отдельное расширение общей коллекции.

## Экраны

### Главная

Поисковая строка, начальная подсказка, индикатор поиска и строки фильмов с постером, названием, годом и рейтингом TMDB. Для пустого результата — сообщение «Ничего не найдено»; для ошибки — пояснение и повтор актуального запроса. Первая страница выдачи, без пагинации на этом этапе. После возврата из карточки сохраняются запрос и результаты.

### Карточка

Детали загружаются по movieID: постер, название, оригинальное название, год, длительность, жанры, описание и рейтинг TMDB. Личная оценка отображается отдельно, восстанавливается из хранилища, меняется и удаляется. Сохранение подтверждается интерфейсом только после успешной записи; ошибка хранения не должна оставлять ложное состояние успеха.

Отсутствующие сведения имеют понятные подписи. Ошибка постера даёт заглушку, но не скрывает текст. Для ошибки загрузки данных есть повтор. Сетевая ошибка не удаляет ранее сохранённую личную оценку.

### Мои оценки

Вторая вкладка приложения. Список с постером, названием, годом, личной оценкой и датой оценки. Переключатель двух сортировок, действие «Сбросить сортировку», переход в ту же карточку и действие «Убрать оценку». Пустое состояние объясняет, что сначала нужно найти и оценить фильм.

Список обновляется после действий в карточке, возврата на вкладку и удаления записи. Дубликатов одного movieID нет. Без интернета доступны сохранённый список, оценки, даты, сортировка и удаление. Сохранённые текстовые детали оценённого фильма доступны без сети; свежие сведения требуют API; постер без доступной загрузки заменяется заглушкой.

## Архитектура и данные

- `MovieSummary` — краткие данные поисковой выдачи; `Movie` — подробные данные карточки. Отдельные DTO описывают фактические ответы API, включая отсутствующие поля.
- `MovieAPIClient` — URLSession, Codable, проверка HTTP-статуса и обработка ошибок. Отдельный actor для сетевой обработки; передаваемые значения безопасны для конкурентного использования.
- `MovieRepositoryProtocol` / `MovieRepository` — поиск и детали. ViewModel не собирает URL и не декодирует JSON.
- `RatedMovie` — SwiftData-модель: уникальный movieID, title, year, posterPath, userRating, comment и ratedAt. Сохраняются также описание, жанры, длительность и оригинальное название для открытия оценённой карточки без сети. Сохраняется минимальный снимок сведений для списка без сети.
- `RatingRepositoryProtocol` / `RatingRepository` — чтение, сохранение, изменение, удаление оценок и соблюдение правил даты/диапазона. Один дисковый ModelContainer для приложения, работа с контекстом на MainActor.
- `SettingsStore` — чтение, запись и удаление режима сортировки в UserDefaults; сброс удаляет ключ и применяет порядок по умолчанию.
- `SearchViewModel`, `MovieDetailsViewModel`, `RatingsViewModel` — наблюдаемое состояние на MainActor и обработка действий.
- Зависимости создаются в точке входа и передаются через инициализаторы. Экраны владеют ViewModel через State.
- `TabView`: «Поиск» и «Мои оценки», в каждой вкладке свой NavigationStack. Карточка открывается по ID из любого списка.

Текущая настройка проекта изолирует типы на MainActor по умолчанию. При реализации проверить изоляцию DTO и границы сетевого actor, чтобы декодирование случайно не оказалось на главном акторе.

## Источник данных и удаление моков

Пользовательские экраны работают только с TMDB и сохранёнными личными данными. MovieMock и привязка к единственному фильму/локальному постеру удаляются из приложения. JSON-фикстуры и подставные репозитории допускаются только в тестах; нет автоматической подмены сетевой ошибки моковыми фильмами.

Токен передаётся через локальную конфигурацию вне Git с шаблоном настройки без секрета. Отсутствие токена отображается понятной ошибкой настройки. Токен не записывается в исходники или журналы. При реализации проверить доступность API и CDN. Отдельный экран Keychain на этом этапе не добавляется.

Операции API:

- Поиск по строке с корректным кодированием кириллицы: [TMDB Search Movies](https://developer.themoviedb.org/reference/search-movie).
- Детали по ID с русской локализацией: [TMDB Movie Details](https://developer.themoviedb.org/reference/movie-details).

## Проверки результата

- Поиск по русскому и английскому названию, пустая строка, отсутствие совпадений, ошибка и повтор.
- Медленный старый успешный/неуспешный ответ не меняет новую выдачу; очистка строки отменяет результаты старого запроса.
- Отсутствующие постер, описание, дата или длительность не ломают карточку.
- Оценки 1 и 10 принимаются; значения вне диапазона отклоняются без изменения хранилища.
- Повторная оценка не создаёт дубль; одинаковая оценка сохраняет прежнюю дату, изменение обновляет её.
- Оба порядка сортировки, одинаковые оценки/даты и удаление проверяются предсказуемыми тестовыми датами.
- После закрытия и запуска приложения сохраняются оценки, даты и выбранный порядок. Отдельно проверить повторное открытие дискового хранилища: тест в памяти не доказывает постоянное сохранение.
- Изменение оценки отражается в списке и карточке при переходах между вкладками.
- Сброс сортировки удаляет ключ UserDefaults и возвращает порядок по умолчанию без изменения записей SwiftData; отсутствие ключа проверяется в тесте.
- При сетевой ошибке личные записи не исчезают; ошибка базы не маскируется успешным сохранением.
- Пользовательский запуск не содержит моковых фильмов, данные в тестах не зависят от живого API.

Приёмочный сценарий: найти фильм → открыть карточку → оценить → найти второй фильм и оценить → открыть «Мои оценки» → сравнить две сортировки → изменить оценку → проверить изменение порядка → перезапустить приложение → убрать оценку и проверить её отсутствие после следующего запуска.

Для защиты подготовить объяснение назначения двух хранилищ и показать Create → Read → Update → Delete для каждого по таблице выше. Эта демонстрация обязательна для сегодняшнего результата.

## Результат реализации — 1 октября 2026

Поиск и карточка используют настоящий TMDB. «Мои оценки» сохраняются в SwiftData с многострочным комментарием; снимок сведений обеспечивает текстовые карточки без сети. Режим сортировки хранится в UserDefaults, сброс удаляет ключ. На устройстве настроен локальный игнорируемый Git файл TMDBConfig.plist.

Проверено: сборка для iOS Simulator; 18 юнит-проверок; обычный UI-тест навигации; отдельный живой UI-прогон поиска, создания, чтения, изменения, перезапуска и удаления комментария с оценкой. Реальные поиск и детали TMDB вернули HTTP 200. В сквозном прогоне исправлена клавиатура, мешавшая сменить вкладку после возврата из карточки. Снимки карточки и списка просмотрены.

Следующий этап общей документации: четвёртый содержательный экран и расширение функций коллекции. Текущая реализация содержит три основных экрана, как согласовано пользователем.
