# FilmGraph — план до готовой учебной версии

> Ближайший этап уточнён пользователем: реальные данные, поиск на главной и «Мои оценки». Актуальный план этого этапа — [SEARCH_AND_RATINGS_PLAN.md](SEARCH_AND_RATINGS_PLAN.md). Он заменяет прежнюю очередность «сначала хранение на моках» и ожидает разрешения на реализацию.

Дата аудита: 1 октября 2026 года.

Основание: `FilmGraph_Project_Documentation.md` и фактическое состояние проекта AbsoluteCinema. Документация описывает целевое приложение; наличие пункта в ней не означает, что он уже реализован. В рамках планирования сборка и тесты не запускались.

## 1. Точка старта

| Область | Сейчас | Что осталось |

Текущий код не содержит варианта с UserDefaults, обсуждавшегося ранее. Основа плана — файлы в рабочей копии. Локальное изменение комментария в MovieMock сохраняется.

## 2. Согласованный объём и приоритет занятия

Пользователь подтвердил: стек из документа разрешён; финальное оформление — тёмная тема, аккуратно и без излишнего декора. Жёсткого срока нет. Текущее занятие посвящено локальному хранению: SwiftData, UserDefaults и Keychain.

Базовый объём готовой версии: каталог, поиск, карточка любого фильма, личная коллекция; реальные данные TMDB; локальное хранение; конкурентная загрузка; тесты; единая тема; демонстрация преподавателю.

Принятые рабочие решения:

- Сохраняем SwiftUI, MVVM, SwiftData и Swift Concurrency.
- Планируем iOS 17+, как в документации; проверяем совместимость на этапе подготовки.
- «Закладки» соответствуют статусу «Хочу посмотреть» в общей коллекции; оценка переводит фильм в «Просмотрено».
- Существующие тесты Swift Testing сохраняем, если преподаватель отдельно не потребует XCTest. UI-тесты — XCTest.
- Ориентир готовности — демонстрация из Xcode/на устройстве. Публикация не запрошена.

### Что делать для сегодняшнего занятия

**Основной результат: новый экран «Моя коллекция» и сохранение действий существующей карточки через SwiftData.** Сеть пока не нужна: используем MovieMock и локальные постеры. Это демонстрирует создание, чтение, изменение и удаление данных, связь двух экранов и сохранение после перезапуска.

1. Ввести LibraryEntry, общий дисковый ModelContainer и LibraryRepository.
2. Подключить карточку: добавить в «Хочу посмотреть», поставить/очистить оценку, изменить статус, удалить из коллекции.
3. Сделать экран коллекции: две группы по статусу, список, переход в карточку и удаление. Сегодня достаточно навигации между этими двумя экранами; полный TabView появится с каталогом и поиском.
4. Для содержательного демо подготовить несколько локальных моков. Если используем начальное заполнение демо-базы, выполнить его один раз, чтобы удалённые записи не появлялись при каждом запуске.
5. Проверить восстановление после настоящего завершения процесса, отсутствие дублей и обновление списка после возврата из карточки.

**Дополнение для демонстрации UserDefaults:** сохранять выбранную сортировку коллекции («Сначала новые» / «По названию») через небольшой SettingsStore. Переключатель можно разместить прямо на экране коллекции; отдельный экран настроек для этого не нужен.

**Дополнение для демонстрации Keychain:** небольшой раздел/лист «Настройки подключения» с SecureField для токена TMDB, сохранением, заменой и удалением токена. Отображать только признак наличия токена, без вывода сохранённого значения. KeychainStore отвечает за операции с Keychain, SettingsViewModel — за состояние и ошибки. Эта функция пока демонстрирует хранение; сетевой клиент начнёт использовать её позже. Не включать реальный токен в мок, Git или текст плана. Если Keychain не требуется на сегодняшнем показе, сделать этот пункт вместе с подключением API.

Выбор технологий соответствует назначению данных: [SwiftData ModelContext](https://developer.apple.com/documentation/swiftdata/modelcontext) — записи фильмов и операции над ними; [UserDefaults](https://developer.apple.com/documentation/foundation/userdefaults) — несекретные настройки; [Keychain](https://developer.apple.com/documentation/security/using-the-keychain-to-manage-user-secrets) — токен.

**Сценарий показа:** открыть карточку → добавить в коллекцию → найти запись в списке → поставить оценку → увидеть «Просмотрено» → изменить сортировку → закрыть приложение и запустить снова → показать сохранившиеся запись, оценку и настройку → удалить фильм и убедиться, что удаление сохраняется. При готовом Keychain дополнительно сохранить/заменить/удалить тестовый токен, проверяя наличие после перезапуска без показа его значения.

## 3. Последовательность работы

### Этап 1. Проверить основу и зафиксировать решения

- Зафиксировать подтверждённые стек, тему и приоритет хранения. Отдельно определить имя, видимое пользователю: FilmGraph либо Absolute Cinema; техническое переименование проекта не является необходимым условием.
- Привести deployment target приложения и тестов к выбранной версии iOS. Проверить доступность используемых API.
- Собрать текущую версию и запустить имеющиеся тесты; проверить наличие AppIcon, цветов и постера.
- Для показа хранения оставить локальные моки. Настройку токена и проверку доступности API выполнить при переходе к сети; сегодня они не блокируют SwiftData.

**Готово, когда:** исходная карточка запускается на выбранном устройстве/симуляторе, тесты проходят, можно начинать изменение слоя хранения.

### Этап 2. Подготовить модели и границы MVVM

- При подготовке к сети разделить краткие данные фильма для списков (`MovieSummary`) и подробные (`Movie`), чтобы каталог не требовал отдельного запроса для каждой карточки.
- При подготовке к сети подготовить DTO ответов TMDB и преобразование в прикладные модели. Учесть отсутствие даты, постера, длительности и пустое описание.
- При подготовке к сети заменить зависимость реальных фильмов от `posterAssetName` на путь/URL постера. Локальный постер оставить для превью и моков.
- Вынести статус коллекции из MovieDetailsViewModel в модель предметной области.
- Сначала ввести `LibraryRepositoryProtocol` для коллекции. `MovieRepositoryProtocol` для подборок, поиска и деталей добавить при подготовке сетевого слоя; для сегодняшнего демо достаточно передачи MovieMock.
- Собрать зависимости в точке входа приложения и передавать через инициализаторы. Один экземпляр хранилища должен обслуживать все экраны.
- Оставить моки как подставные реализации репозиториев для тестов и превью.

**Готово, когда:** статус вынесен в модель, интерфейс репозитория коллекции определён, зависимости передаются через инициализаторы. Сетевые пункты этого этапа выполняются непосредственно перед этапом 5, чтобы не задерживать сегодняшнее демо.

### Этап 3. Сохранять коллекцию через SwiftData

- Создать `LibraryEntry`: уникальный movieID, название, год, posterPath, статус, личная оценка и addedAt.
- Подключить один ModelContainer и LibraryRepository. Для небольшого объёма хранить работу с основным ModelContext на MainActor; не передавать его в сетевой actor.
- Перенести из ViewModel в репозиторий коллекции операции и правила: добавление, обновление статуса, оценка, удаление. Повторное добавление обновляет запись, а не создаёт дубль.
- Оценка допустима только в диапазоне 1–10 и переводит фильм в «Просмотрено». Этот статус допустим без оценки. Возврат в «Хочу посмотреть» очищает оценку. Удаление из коллекции удаляет всю личную запись.
- Подключить карточку к репозиторию: читать сохранённое состояние при открытии, сохранять изменения и отражать успех в UI.
- Обрабатывать ошибку сохранения: сообщение пользователю и сохранение/восстановление предыдущего корректного состояния, без ложного сообщения об успехе.

**Готово, когда:** статус и оценка восстанавливаются после закрытия и повторного запуска; один ID даёт одну запись; удаление сохраняется после перезапуска. На этом этапе завершена цепочка «MovieMock → карточка → личные данные на диске».

### Этап 4. Реализовать экран коллекции

- Добавить LibraryView и LibraryViewModel поверх общего LibraryRepository; на этом этапе источником фильмов остаются моки.
- Переключатель «Хочу посмотреть / Просмотрено», сортировка по добавлению, название, год, постер и личная оценка в строке.
- Переход в карточку и удаление записи; у пустого списка — объяснение, как добавить фильм.
- Перечитывать данные при возвращении из карточки. После появления вкладок также обновлять список при возвращении на вкладку; изменения из каталога и поиска должны отражаться здесь.
- Обеспечить работу списка без сети: название, статус и оценка берутся из SwiftData. Недоступный постер заменяется заглушкой.
- После подключения API для недоступных без сети полных деталей использовать штатное состояние ошибки карточки. На этапе моков данные доступны локально; это не обещание полного офлайн-каталога для финальной версии.
- Добавить выбор сортировки и её сохранение в UserDefaults, если хотим показать вторую технологию хранения сегодня.
- По необходимости добавить компактные настройки токена в Keychain согласно плану сегодняшнего занятия.

**Готово, когда:** фильм, добавленный из карточки, появляется в правильной группе; смена статуса, оценка и удаление согласованы между экранами; список остаётся доступен после перезапуска без интернета.

### Этап 5. Подключить сеть к существующей карточке

- Завершить отложенные изменения моделей и DTO из этапа 2. Проверить доступ к API и CDN в сети для показа. Токен получать через отдельную зависимость: из Keychain, если уже добавлены настройки, иначе из локальной конфигурации вне Git с образцом настройки. Не хранить токен в исходниках.
- Реализовать `MovieAPIClient` через URLSession, async/await и Codable. Он формирует запрос, проверяет HTTP-статус и декодирует ответ.
- Использовать отдельный actor клиента для обработки сетевых данных. ViewModel оставить на MainActor. Учесть текущую настройку проекта `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`: DTO и передаваемые значения не должны случайно оказаться привязаны к главному актору.
- Реализовать реальные методы MovieRepository: популярные, высокорейтинговые фильмы, поиск и детали по ID. Интерфейс сначала подключить только к карточке.
- Карточка принимает `movieID`, показывает загрузку, данные или понятную ошибку с повтором. Уход с экрана отменяет загрузку; отмена не отображается как ошибка.
- Загружать постер по URL с индикатором и заглушкой при отсутствии/ошибке. Ошибка изображения не скрывает текст фильма.
- Для отсутствующих сведений использовать пояснения, не вымышленные нулевые значения. При отсутствии голосов показывать, что рейтинг ещё не сформирован.
- Основной запуск использует реальные данные; мок остаётся доступен в тестах и превью.

**Готово, когда:** одна и та же карточка открывает разные ID, работает повтор после ошибки, а сеть и декодирование проверяются без живого TMDB через подставной транспорт/URLProtocol. Существующие действия продолжают сохраняться в SwiftData.

### Этап 6. Добавить навигацию и каталог

- Создать корневой TabView с тремя вкладками и NavigationStack в каждой. Карточку открывать по ID; не делать ей отдельную вкладку.
- Реализовать CatalogView и CatalogViewModel с разделами «Популярные» и «Высокий рейтинг».
- Загружать подборки конкурентно через async let. Использовать текущий API-клиент и репозиторий.
- Сделать переиспользуемую карточку/строку списка: постер, название, год и рейтинг.
- Показать состояния загрузки, пустой подборки и ошибки. Если одна подборка не загрузилась, сохранить доступную вторую и дать повтор для неудавшейся.
- Сохранить навигацию вкладок при переключении; одинаковый фильм из разных источников открывает одну реализацию карточки.

**Готово, когда:** каталог показывает реальные фильмы, обе загрузки стартуют конкурентно, переход и возврат работают, ошибка одной подборки не делает весь каталог пустым.

### Этап 7. Реализовать поиск

- Добавить SearchView и SearchViewModel, поле ввода и запуск по «Найти»/кнопке клавиатуры.
- Обрезать пробелы; пустой запрос не отправлять. Сначала показывать подсказку, после поиска — результат, отсутствие совпадений либо ошибку с повтором.
- Корректно кодировать кириллицу и спецсимволы в query.
- Отменять предыдущую задачу при новом запросе. Дополнительно проверять идентификатор актуального запроса перед применением результата: одной отмены недостаточно для защиты от старого ответа.
- Очистка строки также отменяет поиск и делает старые ответы неактуальными.
- Переходить в общую карточку по ID. В первой версии использовать одну страницу результатов.

**Готово, когда:** русский и английский запросы работают, пустой поиск не вызывает сеть, медленный старый ответ не заменяет новый результат. Проверить гонку контролируемыми ответами в тесте, без случайных задержек.

## 4. Проверки по ходу разработки

Тесты добавляются к соответствующему этапу, а не откладываются целиком на конец. Цель — покрыть поведение, количество само по себе не критерий.

| Область | Проверки |
|---|---|
| Данные | Ответ API преобразуется в модель; отсутствующий постер/дата и пустое описание не ломают экран |
| Сеть | Успех, неуспешный HTTP-статус, ошибка декодирования и отмена; токен не нужен юнит-тестам |
| Состояния | Загрузка завершается как при успехе, так и при ошибке; повтор восстанавливает данные |
| Каталог | Обе подборки загружаются; частичная ошибка сохраняет успешный результат |
| Поиск | Пустая строка, нет результатов, старый ответ после нового, очистка во время запроса |
| Правила коллекции | Диапазон оценки, автоматический статус, очистка оценки при смене статуса, удаление |
| SwiftData | Создание/чтение/изменение/удаление, отсутствие дублей и независимость разных movieID; отдельное хранилище в памяти для тестов |
| Настройки | Сортировка сохраняется в отдельном UserDefaults; при реализации Keychain проверяются сохранение, замена, чтение и удаление тестового токена, обработка ошибок |
| Диск | Повторное открытие дискового хранилища/ручной перезапуск подтверждают постоянное сохранение; тест базы в памяти этого не доказывает |
| UI | Каталог → карточка → добавление → оценка → коллекция; данные теста предсказуемы |

Имеющиеся тесты поведения карточки адаптируются после переноса правил в репозиторий. Проверку равенства мока исходному JSON заменить/дополнить проверками настоящего декодирования и преобразования DTO.

## 5. Критерий готовности для защиты

1. Из каталога открыть карточку произвольного фильма.
2. Найти другой фильм через API и добавить в «Хочу посмотреть».
3. Убедиться, что фильм появился в коллекции без дублей.
4. Поставить оценку и увидеть переход в «Просмотрено».
5. Вернуть статус «Хочу посмотреть» и проверить очистку оценки.
6. Закрыть и запустить приложение без сети: коллекция, статусы и оценки сохранены.
7. Показать корректную сетевую ошибку и успешный повтор после восстановления связи.
8. Удалить фильм и подтвердить, что он не вернулся после перезапуска.
9. Запустить тесты без обращения к живому API.
10. Объяснить путь View → ViewModel → Repository → API/SwiftData и показать конкурентную загрузку подборок.

## 6. Дополнение после готовности основной версии

Рекомендации по фильму — отдельный следующий этап: загрузить подборку на карточке, переходить в ту же карточку по ID, не блокировать основные сведения при ошибке рекомендаций.

Регистрация, сервер, синхронизация, социальные функции, обучение рекомендаций, сложные фильтры, бесконечная прокрутка и полный офлайн-каталог не входят в согласуемую учебную версию. TestFlight/App Store добавляются в план, если это входит в формат сдачи.
